# UX設計方針 - AI成果物判定プロダクト

## 1. プロダクト概要

AI（大規模言語モデル等）が生成した文章・画像・コードなどの成果物に対して、
ユーザーが「承認 / 修正指示 / 却下」といった判断を効率的に行えるプロダクト。

## 2. 想定ユーザー

| ペルソナ | 説明 | 主な利用シーン |
|---------|------|--------------|
| マネージャー | AI成果物の最終承認者。品質担保に責任を持つ | 承認フロー、品質レビュー |
| オペレーター | AIへの指示出しと一次チェックを行う | 生成指示、一次判定、修正依頼 |
| 監査担当 | 判定履歴を確認し、運用品質を監査する | ログ確認、統計閲覧 |

## 3. コアとなるユーザー体験

### 3.1 基本フロー

```
[1] AI成果物の受取
    ユーザーが成果物一覧を確認する
        |
[2] 内容の確認・比較
    元の指示（プロンプト）と成果物を並べて確認する
        |
[3] 判定の実行
    承認 / 修正指示 / 却下を選択し、理由を記録する
        |
[4] フィードバックの記録
    判定結果が履歴に蓄積され、ダッシュボードに反映される
```

### 3.2 UX設計の5原則

1. **即座に判断できる情報配置**
   - 成果物と判断ボタンを同一画面に配置し、画面遷移を最小化する
   - 「見る → 判断する → 次へ」のリズムを途切れさせない

2. **比較のしやすさ**
   - 元の指示（プロンプト）と生成結果を左右または上下に並べて表示
   - diff表示（変更前後の差分ハイライト）で修正箇所を即座に把握可能に

3. **判断の負荷軽減**
   - AI自身による品質スコア（自信度）を参考情報として表示
   - 過去の類似判定パターンをサジェストし、判断の一貫性を支援

4. **取り消し可能な安心感**
   - すべての判定はUndoが可能。確定前に確認ダイアログを表示
   - 判定履歴から過去の判断を修正できる仕組み

5. **バッチ処理への対応**
   - 大量の成果物を一括判定できるモードを用意
   - フィルタ・ソート機能で優先度の高いものから処理可能に

### 3.3 ユーザーの感情設計

| フェーズ | ユーザーの感情目標 | 実現手段 |
|---------|-----------------|---------|
| 初回利用 | 「直感的に使える」と感じる | オンボーディングチュートリアル、最小限のUIで迷わせない |
| 日常利用 | 「効率的に捌ける」と感じる | キーボードショートカット、バッチ処理、フィルタ |
| 判定時 | 「根拠をもって判断できた」と感じる | 比較表示、品質スコア、過去の判定参考 |
| 判定後 | 「記録が残っている」安心感 | 判定履歴、ダッシュボード、エクスポート機能 |

## 4. 情報アーキテクチャ

```
ホーム（ダッシュボード）
├── 未判定一覧（受信トレイ型）
│   ├── 成果物詳細・判定画面
│   └── バッチ判定画面
├── 判定履歴
│   ├── タイムライン表示
│   └── 統計・分析
├── プロジェクト管理
│   ├── プロジェクト一覧
│   └── プロジェクト設定
└── 設定
    ├── 判定基準テンプレート
    ├── 通知設定
    └── チームメンバー管理
```

## 5. アクセシビリティ方針

- WCAG 2.1 AA準拠を目標とする
- キーボードのみでの全操作に対応
- スクリーンリーダー対応（ARIA属性の適切な付与）
- 色覚多様性への配慮（色だけに依存しない情報伝達）
