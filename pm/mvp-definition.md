# MVP定義書: AI Output Judge

## 更新日: 2026-05-05
## 管理者: PM室

---

## 1. MVPの目的

最小限の機能セットで「AIの成果物を判定する」という核心的な価値を検証する。
MVPで確認すべき仮説:

1. **価値仮説**: ユーザーはAI成果物の品質を客観的に判定してくれるツールに価値を感じるか
2. **実現可能性仮説**: AIによるAI成果物の判定は、実用的な精度を達成できるか
3. **UX仮説**: テキストを入力して判定結果を受け取るフローは、直感的に使えるか

---

## 2. MVP機能一覧

### 必須機能（Must Have）

| # | 機能 | 説明 | 担当部署 |
|---|------|------|----------|
| M1 | テキスト入力 | AI生成テキストをテキストエリアに貼り付けて投入できる | 開発部 |
| M2 | テキスト品質判定 | 投入されたテキストに対して品質スコアと評価コメントを返す | 開発部 |
| M3 | 判定軸の表示 | 以下の軸でスコアを表示: (a) 正確性・事実性 (b) 一貫性・論理性 (c) 明瞭さ・可読性 (d) 総合スコア | 開発部 |
| M4 | 判定結果の詳細表示 | 各スコアの根拠となる具体的な指摘・コメントを表示 | 開発部 + デザイン部 |
| M5 | 判定履歴の保存 | 過去の判定結果を一覧で閲覧できる（ローカルストレージまたはDB） | 開発部 |
| M6 | Web UI | ブラウザから操作できるシンプルなWebインターフェース | 開発部 + デザイン部 |

### あると望ましい機能（Should Have） - MVP後に優先実装

| # | 機能 | 説明 |
|---|------|------|
| S1 | ユーザー認証 | ログイン/ログアウト、ユーザーごとの履歴管理 |
| S2 | 判定基準のカスタマイズ | 各判定軸の重み付けやカスタム基準の追加 |
| S3 | フィードバック機能 | 判定結果に対する「正しい/正しくない」のフィードバック投入 |
| S4 | コピー/エクスポート | 判定結果のクリップボードコピー・PDF出力 |

### 将来機能（Won't Have in MVP）

| # | 機能 | 説明 |
|---|------|------|
| W1 | コード判定 | 生成コードの品質判定（Phase 4で対応） |
| W2 | ダッシュボード | 統計・傾向分析の可視化（Phase 4で対応） |
| W3 | API提供 | 外部システムからの判定APIコール |
| W4 | チーム機能 | 組織・チーム単位での管理 |
| W5 | 画像・動画判定 | テキスト以外のメディア判定 |

## 3. MVPの技術スタック（推奨案）

| レイヤー | 技術 | 選定理由 |
|----------|------|----------|
| フロントエンド | Next.js (React) + TypeScript | 高速な開発、SSR対応、エコシステムの充実 |
| バックエンド | Next.js API Routes または FastAPI (Python) | フロントと統合しやすい / AIライブラリとの親和性 |
| AI API | OpenAI API / Anthropic API | テキスト評価タスクの高い対応力 |
| データベース | PostgreSQL (Supabase等) | 判定履歴の永続化、構造化データの保存 |
| ホスティング | Vercel / AWS | 迅速なデプロイ、スケーラビリティ |

※ 技術スタックの最終決定は開発部が行う。上記はPM室からの推奨案。

## 4. MVPの画面構成

### 画面1: 入力画面（メイン画面）
- テキスト入力エリア（大きめのテキストエリア）
- 「判定する」ボタン
- 入力文字数の表示
- 判定中のローディング表示

### 画面2: 判定結果画面
- 総合スコア（100点満点、視覚的なゲージ表示）
- 各判定軸のスコア（正確性、一貫性、明瞭さ）
- 各軸の詳細コメント・指摘事項
- 「新しい判定を行う」ボタン
- 「履歴を見る」リンク

### 画面3: 履歴画面
- 判定日時、入力テキストの先頭部分、総合スコアの一覧表示
- 各履歴の詳細表示へのリンク
- 履歴の削除機能

## 5. MVP完了基準（Definition of Done）

MVP完了と判定するために、以下のすべてを満たすこと:

### 機能要件
- [ ] テキスト入力 → 判定実行 → 結果表示の一連のフローが動作する
- [ ] 3つの判定軸（正確性、一貫性、明瞭さ）でスコアが算出される
- [ ] 各スコアに具体的な根拠コメントが付与される
- [ ] 判定履歴の保存・閲覧ができる

### 非機能要件
- [ ] 判定レスポンスが10秒以内に返る（MVP段階の暫定目標）
- [ ] 主要ブラウザ（Chrome, Firefox, Safari最新版）で動作する
- [ ] 日本語・英語のテキストに対応する

### 品質要件
- [ ] テストデータセット（50件以上）で判定精度75%以上（人間判定との一致率）
- [ ] 明らかに高品質なテキストと低品質なテキストを正しく判別できる
- [ ] エラー発生時に適切なエラーメッセージが表示される

### 承認要件
- [ ] 社長によるデモ確認・承認
- [ ] PM室による品質チェック完了

## 7. MVPの成功判定

MVPリリース後2週間で以下を評価し、次フェーズ移行を判断する:

| 評価項目 | 成功基準 | 判定方法 |
|----------|----------|----------|
| 判定精度 | 人間判定と75%以上一致 | テストデータセット |
| ユーザー体験 | 社長が「使える」と評価 | デモ・ハンズオン |
| 技術実現性 | 主要機能が安定動作 | E2Eテスト通過率95%以上 |
| 開発速度 | 8週間以内に完成 | 実績スケジュール |

### 判定結果に基づくアクション
- **全基準達成**: Phase 4（拡張開発）に移行
- **一部未達**: 原因分析 → 追加改善スプリント（最大2週間）を実施
- **重大な問題**: 社長と協議し、スコープ見直しまたはピボットを検討
